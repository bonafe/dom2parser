De HTML gigante a parser verificado
sem chamar nenhum LLM

O DOM2parser recebe uma página HTML de centenas de KB a alguns MB, encontra as estruturas repetidas que carregam os dados e sintetiza um parser verificado para extraí-las — seletor de registro, locator e nome por campo — junto de uma representação estrutural compacta da página. A síntese é uma busca determinística medida contra o documento original, não um palpite de modelo.

O problema

Páginas reais carregam centenas de KB (às vezes mais de 1 MB) de scripts, CSS, SVGs, menus de navegação, widgets de filtro e wrappers de layout — e apenas uma fração mínima disso é a estrutura de dados que você realmente quer extrair. E mesmo quando se isola essa estrutura, sobra uma pergunta que pedir a um modelo não resolve bem: qual seletor exato alcança todos os registros e nenhum a mais? — sete amostras e um path truncado não dão a um LLM como verificar a própria resposta.

O DOM2parser resolve as duas coisas com o mesmo pipeline: primeiro destila a estrutura — onde ela está, quantas vezes se repete, o formato de cada campo, exemplos e outliers reais — depois sintetiza e verifica o seletor contra o documento original, porque a biblioteca tem os elementos-alvo em mãos e pode medir, em vez de chutar. Os nomes de campo, a única parte genuinamente semântica, são lidos da própria página.

Como funciona

Duas metades, num pipeline de 13 fases — cada uma resolvendo um problema real encontrado ao testar contra HTML de produção, não hipotético (veja as decisões de arquitetura):

  1. Sanitização estruturalRemove scripts, estilos, SVG, comentários, navegação/menus, widgets ocultos e atributos irrelevantes.
  2. Dedup de subtree idênticoColapsa decoração repetida byte-a-byte (ex. ícones SVG idênticos) sem tocar em registros de dados legítimos.
  3. Fingerprint estrutural com fallbackdata-testid → role → classe semântica → id (só se reutilizado) → forma — ignorando hashes de build, classes atômicas, de estado e utilitárias.
  4. Content signatureClassifica cada campo de texto (DATE, MONEY, FILE_FORMAT, COUNT_LABELED...) sempre a partir do conteúdo, nunca da classe CSS.
  5. Clusterização toleranteAgrupa elementos "quase idênticos", tolerando campos opcionais sem fragmentar o cluster.
  6. Ranking de relevânciaSepara o conteúdo real do ruído dominante (menus repetem mais que dados — contagem bruta engana).
  7. Sampling representativoPrimeiro/meio/último + outliers estruturais e numéricos reais, não apenas os N primeiros itens.
  8. AncoragemCarimba cada elemento do original antes da sanitização, para poder voltar a ele depois.
  9. Fecho e promoçãoRecupera registros que o agrupamento perdeu e sobe da família (frequentemente um wrapper interno) até o registro real.
  10. Síntese de seletorGera candidatos e mede cada um contra o documento original; só aceita recall 1.0, e emite precisão 1.0 ou declara falha.
  11. Descoberta de camposLocator, tipo e captura de atributo (href/src) por campo, validados nos registros inteiros, não só na amostra.
  12. NomeaçãoCabeçalho, itemprop, aria-label ou classe — só quando o valor é constante entre os registros; senão cai para tipo+posição.
  13. Execução e validaçãoO ParserSpec (dado, não código) roda no HTML original e devolve conformidade de tipo por campo.

Exemplo rápido

import dom2parser

html = open('fatura.html').read()
result = dom2parser.compress(html)

print(result.text)          # representação compacta em texto, com o seletor verificado
print(result.reduction)     # {'reduction_pct': {'chars': 97.3, 'tokens': 97.3}, ...}

from dom2parser.parser.executor import execute
record = result.parser.records[0]
print(execute(result.parser, html)[record.name].kept[0].values)
# {'data': '28/07', 'transacoes': 'PGTO DEBITO CONTA...', 'moeda': 'R$', 'valor': '-11.966,18'}

Ainda não publicado no PyPI — instalação a partir do repositório clonado em uso e API.

Escopo do projeto: o DOM2parser comprime a página e gera o parser que extrai os registros dela — mas continua sem chamar nenhum LLM. A síntese é determinística e verificada: cada seletor candidato é rodado contra o documento original e só é aceito se alcançar todos os registros. Os nomes dos campos são lidos da própria página (linha de cabeçalho, itemprop, aria-label, classe), com queda para tipo e posição quando a página não diz nada. Ver ADR-009.
