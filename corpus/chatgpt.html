Ou seja: aquela diferença enorme que existia entre um “editor com autocomplete de IA” e um “IDE agentic” praticamente desapareceu.

Onde o Antigravity ainda é diferente

O Antigravity continua sendo mais radicalmente agent-first.

A ideia não é você ficar olhando arquivo por arquivo enquanto a IA completa código. O objeto principal passa a ser algo próximo de:

Projeto → tarefa → agentes → artefatos → revisão

O agente pode trabalhar no editor, terminal e browser, executar tarefas maiores e produzir artefatos que você revisa posteriormente. Ele também suporta agentes locais assíncronos trabalhando em paralelo. Google Antigravity+1

O Antigravity 2.0 foi ainda mais longe: o Google praticamente separou a ideia de “editor” da de “orquestrador de agentes”. Existe agora:

Antigravity 2.0 + Antigravity CLI + Antigravity SDK + Antigravity Agent API + extensões para IDEs. Google Antigravity+1

Para o seu cenário, eu considero essa arquitetura bem mais interessante do que migrar completamente para o Antigravity. Você mantém Remote SSH, Docker, debugger, Git, extensões, terminal, seus ambientes Python/Java, Ollama e tudo que já funciona no VS Code, mas adiciona o Antigravity quando quiser delegar tarefas maiores.

A mudança mais importante dos últimos meses é justamente esta: VS Code e Antigravity deixaram de ser concorrentes mutuamente exclusivos. O VS Code pode ser o control plane do seu desenvolvimento, enquanto Antigravity, Claude, Codex e seus próprios agentes são diferentes workers/harnesses. Para o que você está querendo fazer com vários agentes e seu cluster Ollama, eu seguiria exatamente nessa direção.
