Comprima HTML gigante numa representação
que um LLM consegue realmente usar

O DOM2parser recebe uma página HTML de centenas de KB a alguns MB e produz uma representação estrutural compacta — preservando hierarquia, cardinalidade de estruturas repetidas, assinaturas de conteúdo e exemplos representativos — para que um programa com LLM gere um parser (CSS/XPath/lxml) reutilizável, sem gastar milhares de tokens com HTML bruto.

O problema

Páginas reais carregam centenas de KB (às vezes mais de 1 MB) de scripts, CSS, SVGs, menus de navegação, widgets de filtro e wrappers de layout — e apenas uma fração mínima disso é a estrutura de dados que você realmente quer extrair. Enviar o HTML inteiro para um LLM gerar um parser é caro e, pior, a repetição de centenas de registros idênticos não ajuda o modelo a entender a estrutura — só consome tokens.

O DOM2parser resolve isso com uma pergunta simples: o que o LLM realmente precisa ver para gerar um seletor correto? A resposta não é "o HTML inteiro", nem "um resumo genérico de texto" — é uma via destilação estrutural: onde a estrutura relevante está, quantas vezes ela se repete, qual o formato de cada campo, e alguns exemplos + outliers reais.

Como funciona

Um pipeline de 7 etapas, cada uma resolvendo um problema real encontrado ao testar contra HTML de produção (não hipotético — veja as decisões de arquitetura):

  1. Sanitização estruturalRemove scripts, estilos, SVG, comentários, navegação/menus, widgets ocultos e atributos irrelevantes.
  2. Dedup de subtree idênticoColapsa decoração repetida byte-a-byte (ex. ícones SVG idênticos) sem tocar em registros de dados legítimos.
  3. Fingerprint estrutural com fallbackdata-testid → role/aria → classe semântica → id → forma — ignorando hashes de build e classes CSS atômicas.
  4. Content signatureClassifica cada campo de texto (DATE, MONEY, FILE_FORMAT, COUNT_LABELED...) sempre a partir do conteúdo, nunca da classe CSS.
  5. Clusterização toleranteAgrupa elementos "quase idênticos", tolerando campos opcionais sem fragmentar o cluster.
  6. Ranking de relevânciaSepara o conteúdo real do ruído dominante (menus repetem mais que dados — contagem bruta engana).
  7. Sampling representativoPrimeiro/meio/último + outliers estruturais e numéricos reais, não apenas os N primeiros itens.

Exemplo rápido

pip install dom2parser

python -c "
import dom2parser

html = open('fatura.html').read()
result = dom2parser.compress(html)

print(result.text)        # representação compacta em texto
print(result.reduction)   # {'reduction_pct': {'chars': 96.8, 'tokens': 96.8}, ...}
"
Escopo do projeto: o DOM2parser comprime a página e gera o parser que extrai os registros dela — mas continua sem chamar nenhum LLM. A síntese é determinística e verificada: cada seletor candidato é rodado contra o documento original e só é aceito se alcançar todos os registros. Os nomes dos campos são lidos da própria página (linha de cabeçalho, itemprop, aria-label, classe), com queda para tipo e posição quando a página não diz nada. Ver ADR-009.
